## 二、网络架构

```
云服务器 localhost
│
├── 已有基础设施容器（独立网络/宿主机网络）
│   ├── postgres_host:5432      ← 应用容器通过宿主机 IP 访问
│   ├── redis-server:6379
│   ├── milvus-standalone:19530
│   └── grobid-cpu:8070
│
└── scipdf-network (Docker bridge)
    ├── scipdf-frontend:80/443  ← 对外暴露
    │   └── 反向代理 /api/ → backend:8000
    │   └── 反向代理 /ws   → backend:8000 (WebSocket)
    ├── scipdf-backend:8000     ← 仅内部网络可达
    │   └── 通过宿主机 IP localhost 连接 PG/Redis/Milvus/GROBID
    └── scipdf-celery-worker    ← 无端口
        └── 通过宿主机 IP 连接 Redis (broker) + PG (结果存储)
```

**关键网络要求**：
- Docker bridge 网络的容器必须能访问宿主机 IP `localhost` 的 5432、6379、19530、8070 端口
- 如果宿主机防火墙限制了 Docker 网段（`172.17.x.x` 或 `172.18.x.x`），需放行上述端口
- 服务器安全组需开放 80（HTTP）和 443（HTTPS）端口

## 三、部署执行步骤

### 阶段 1：代码推送（本地 Windows，已完成）


### 阶段 2：服务器环境准备（SSH 到云服务器）

```bash

# 6. 如果已克隆，拉取最新代码

git checkout v0.3
```

## 六、风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Docker bridge 网络无法访问宿主机 IP | 后端无法连接 PG/Redis | 检查 iptables 规则，确保 Docker 网段可访问宿主机端口 |
| 镜像构建失败（网络超时） | 部署中断 | 配置 Docker 镜像加速器（阿里云镜像源） |
| Celery Worker 内存不足 | 任务执行 OOM | 监控内存使用，必要时增加服务器内存或降低 concurrency |
| SSL 证书过期 | HTTPS 中断 | cron 自动续期已配置，定期检查续期日志 |
| 数据库连接池耗尽 | API 超时 | 当前配置 `pool_size=5, max_overflow=10`，高负载时需调整 |
| 文件存储在 Docker 卷 | 容器删除后数据丢失 | `backend-data` 和 `backend-logs` 使用命名卷，不会随容器删除 |
