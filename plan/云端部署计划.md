# 云端部署计划 — v0.2-postgres 分支

## 目标
将后端（FastAPI）、前端（Vue 3 + Nginx）、Celery Worker 以 Docker Compose 方式部署到云服务器 `localhost`，配置 HTTPS（Let's Encrypt）。

## 当前服务器状态
已运行的 Docker 容器（不要动）：
- `postgres_host` (postgres:16) → 端口 5432
- `redis-server` (redis:7-alpine) → 端口 6379
- `milvus-standalone` → 端口 19530
- `milvus-etcd`, `milvus-minio`
- `grobid-cpu` → 端口 8070

需部署的新容器：
- `scipdf-frontend` (Nginx) → 端口 80/443
- `scipdf-backend` (FastAPI) → 端口 8000
- `scipdf-celery-worker` (Celery) → 无外部端口

## 已完成的配置文件

### 1. docker-compose.yml
- 仅部署应用容器（frontend / backend / celery-worker）
- PostgreSQL / Redis / Milvus / Grobid 使用已有基础设施，通过宿主机 IP `localhost` 连接
- 添加 certbot 服务（`profiles: ["certbot"]`），按需通过 `docker compose run --rm` 调用
- 共享卷：`certbot-etc`、`certbot-var`、`certbot-webroot`

### 2. nginx.conf — 主配置骨架
- 仅包含 `http {}` 块基础设置（upstream、gzip、速率限制）
- 通过 `include` 加载两个动态生成的文件：
  - `http_server.conf` — 端口 80 完整 server 块
  - `https_server.conf` — 端口 443 完整 server 块（无证书时为空）

### 3. nginx/entrypoint.sh — 动态配置生成
容器启动时自动检测 `/etc/letsencrypt/live/` 目录：
- **无证书**：`http_server.conf` 包含完整应用配置（前端/API/WebSocket/健康检查），`https_server.conf` 为空
- **有证书**：`http_server.conf` 仅做 ACME 验证 + 301 重定向到 HTTPS，`https_server.conf` 包含完整应用配置 + SSL
- 启动前执行 `nginx -t` 语法检查

### 4. frontend/Dockerfile
- 多阶段构建：Node 18 Alpine 编译 → Nginx Alpine 运行
- 复制 `nginx/entrypoint.sh` 作为容器 CMD
- 移除默认 `default.conf` 避免冲突
- 创建 `/var/www/certbot` 目录用于 ACME 验证

### 5. .env.prod — 生产环境模板
- 密码字段使用 `<填写...>` 占位符，部署前复制为 `.env` 并填写实际值
- 所有服务连接地址使用宿主机 IP `localhost`

### 6. deploy.sh — 一键部署脚本
支持命令：
| 命令 | 说明 |
|------|------|
| `./deploy.sh` | 构建镜像 + 启动服务（默认） |
| `./deploy.sh ssl-init <域名> <邮箱>` | 首次获取 SSL 证书 |
| `./deploy.sh ssl-renew` | 手动续期证书 |
| `./deploy.sh restart` | 重启所有服务 |
| `./deploy.sh logs` | 查看实时日志 |
| `./deploy.sh status` | 查看服务状态 + 健康检查 + 证书状态 |

## 网络架构
```
宿主机 localhost
├── 已有容器（独立网络）
│   ├── postgres_host:5432
│   ├── redis-server:6379
│   ├── milvus-standalone:19530
│   └── grobid-cpu:8070
│
└── scipdf-network (bridge)
    ├── scipdf-backend:8000 ──── 通过宿主机 IP 连接上述服务
    ├── scipdf-frontend:80/443 ──── 代理到 backend:8000
    └── scipdf-celery-worker ──── 连接 backend 的 Redis/PG
```

## HTTPS 方案（certbot webroot 模式）
1. 首次部署：frontend 以 HTTP 模式启动（无证书），暴露 80 端口
2. 执行 `./deploy.sh ssl-init domain.com email`
3. certbot 容器通过共享卷写入 ACME 验证文件到 `/var/www/certbot`
4. Let's Encrypt 通过 `http://domain/.well-known/acme-challenge/` 验证域名
5. 证书生成到 `certbot-etc` 共享卷
6. 重启 frontend，entrypoint 检测到证书，自动切换到 HTTPS 模式
7. 自动续期：host cron 每天凌晨 3:00 执行 `docker compose run --rm certbot renew`

## 部署步骤（在服务器上执行）
```bash
# 1. 克隆代码（首次）
git clone <仓库地址> /opt/scipdf
cd /opt/scipdf
git checkout v0.2-postgres

# 2. 创建生产环境配置
cp .env.prod .env
nano .env  # 填写数据库密码、Redis 密码、API 密钥等

# 3. 一键部署（HTTP 模式）
chmod +x deploy.sh
./deploy.sh

# 4. 启用 HTTPS（需要域名 DNS 已指向服务器 IP）
./deploy.sh ssl-init yourdomain.com your@email.com

# 5. 验证
./deploy.sh status
curl -k https://yourdomain.com/health
```

## 回滚方案
```bash
docker compose down
git checkout <旧commit>
docker compose up -d --build
```

## 注意事项
- 后端通过宿主机 IP 连接 PG/Redis/Milvus/Grobid，确保防火墙允许 Docker 网络访问这些端口
- 如果后端容器重建导致 IP 变化，需执行 `docker compose restart frontend` 刷新 nginx DNS 缓存
- `.env` 文件已加入 `.gitignore`，不会被提交到仓库
- 证书续期 cron 任务在 `ssl-init` 时自动添加到 host crontab
